# 0.5.54 — 2026-11-20

Everything merged since 0.5.53, by area:

- **Install and security:** `SECURITY=off` quick start for Docker and pip; the generated admin password stays out of the stored log; `docker compose up` works with no aGate.
- **Scheduler:** a force runs until its window closes; a write with no reply is *unknown*, not sent twice; shutdown release recorded in the Audit trail.
- **Home Assistant:** a failed poll no longer publishes empty values.
- **Generator:** no "Running / ON" with no generator connected.
- **Packaging:** ready to publish on PyPI.

### Added

- **Quick start outside Home Assistant: `SECURITY=off`** (owner 2026-11-20). For Docker and
  pip, `SECURITY=off` on the first start makes a new install start with Security off: port
  8101 opens without signing in and no admin is created. Trusted networks stay the private
  ranges, and Settings → Admin → Security says it is off from a quick start until you turn it
  on. It is read only on the first start and ignored by the add-on. INSTALL.md gains a
  **First sign-in** step (`ADMIN_USERNAME` / `ADMIN_PASSWORD`, the generated password in
  the log, `reset-password`), and `docker-compose.yml` lists the three variables
  ([install](https://github.com/david2069/franklinwh-direct-connect-bridge/blob/main/INSTALL.md#first-sign-in-docker-and-pip),
  [guide](../guide/security.md#the-first-admin)).

- **Ready to publish on PyPI** (#782). Once a release is published there, a standalone
  install is `pip install "franklinwh-direct-connect-bridge[cloud]"` with no clone
  ([INSTALL.md → From PyPI](https://github.com/david2069/franklinwh-direct-connect-bridge/blob/main/INSTALL.md#from-pypi)); installing from a clone or a GitHub ref
  works as before. The package now carries project links and classifiers, its author email is
  the GitHub noreply address, and the README's links work on the PyPI page. Nothing is
  published yet.

### Fixed

- **Generator: "Running / ON" is no longer shown with no generator connected** (#245). On the
  reference aGate `genStat` reads 1 as soon as the generator feature is enabled, with nothing
  wired, and the bridge showed **Running / ON** (Generator tab, OFF-GRID details, Home
  Assistant's Generator State, the scheduler's `generator.state_desc`). With no generator
  model or rated power it now shows **genStat 1 (unconfirmed)**, and `genStat` no longer
  counts as evidence of generator hardware. What the FranklinWH app shows at that moment is
  still to be checked ([guide](../guide/generator.md)).

- **Docker: `docker compose up` works with no aGate, and MQTT is off until configured**
  (#154). `docker-compose.yml` fell back to a placeholder aGate address, so the setup wizard
  never opened, and it turned MQTT on against a development broker (port 1884). With no
  `FWH_HOST` the wizard now opens, MQTT is off until `MQTT_ENABLED=true` (default port 1883),
  and the file's build command is INSTALL.md's `docker build`
  ([install](https://github.com/david2069/franklinwh-direct-connect-bridge/blob/main/INSTALL.md#2-docker-standalone)).

- **Home Assistant: a failed poll no longer publishes empty values** (#176). It sent a
  retained state built from the failed reading, then marked the gateway offline, so
  entities could flash empty values and keep them after a restart of Home Assistant. A
  failed poll now publishes only *offline*; the last good state stays until a poll
  succeeds ([Home Assistant](../guide/home-assistant.md)).

- **Scheduler: a force runs until its window closes** (#160). Its auto-release came from
  the schedule's **Duration (min)**, which *Recurring windows* hides and which starts at 90,
  so a force in a 17:00 → 20:00 window was released after 90 minutes. It now runs until the
  window closes (also when it started late in the window), or until its target SoC or an
  exit condition ends it ([actions](../guide/scheduler/actions.md)).

- **The generated first-admin password is no longer kept in the bridge's log** (owner
  2026-11-20). On Docker and pip, with no `ADMIN_USERNAME` / `ADMIN_PASSWORD`, the
  password the bridge makes was also stored in the Bridge log, so it showed under Logs and
  survived restarts. It is now printed once to the console only (`docker logs`, or the
  terminal); the Bridge log says where to find it, and a copy an older version stored is
  masked when the bridge starts. The Home Assistant add-on never logged one
  ([guide](../guide/security.md#the-first-admin)).

- **Scheduler: a device write with no reply is recorded as *unknown*, not retried** (#201).
  A force, mode, smart circuit or off-grid write that timed out after the request left
  was logged *error* and sent again next tick, though it may have landed: a second force.
  It now ends the run *unknown* and isn't sent again; a refused connection or connect
  timeout is still retried. The retry helper's audit hook, which failed silently on every
  call, now works and adds a *retried* row when it took more than one try
  ([outcomes](../guide/scheduler/outcomes.md#retries)).

- **Shutdown: the scheduler stop and each force release are in the Audit trail** (#778).
  Releasing the forces this bridge holds at shutdown kept no record of the outcome. The
  Audit trail now says whether the scheduler stopped or was still running after 5 s, and
  for each force whether the release was confirmed by the aGate's read-back, sent but not
  confirmed, or failed ([guide](../guide/control.md)).
